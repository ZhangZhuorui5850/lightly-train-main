# 物体版 YOLO-seg → MVTec AD 转换设计

日期: 2026-07-08
状态: 已批准设计,待写实现计划

## 背景与问题

多模态团队需要 MVTec AD 格式的数据,由内部 YOLO-segmentation 数据集(多边形 TXT 标签)转换而来。

现有转换器(`convert_tools/yoloseg_to_mvtec.py`,"Option B")把**每个缺陷类别**当作一个 MVTec category(约 24 个 category)。领导指出这在语义上是错的:

- 在真正的 MVTec AD 里,**一个 category = 一个物理物体/部件**(bottle、cable、transistor…),缺陷是物体内部的**子文件夹**(`test/<defect>/`)。
- 现实是**多对多**:一个物体上有多种缺陷;一种缺陷(如锈蚀、裂纹、变形)会出现在多个物体上。
- 源数据只有"缺陷类别"标签,**没有"物体/部件"标签**,所以哪张图属于哪个物体这个信息机器无法从标签得知,必须由人来判定。

### 两个被暴露的根本约束(已确认)

1. **没有干净图**:源数据每张图都至少带一个缺陷,不存在无标注/空标签的正常图。
2. **用途 = 零样本/多模态 AD**:多模态团队用 CLIP/语言驱动的零样本异常检测,主要依赖 `test/` + `ground_truth/` + 缺陷描述,**不需要 `train/good`**。

关键洞察:现有 Option B 能跑,是靠"相对 good"障眼法(对缺陷 X,不含 X 的图算 good,哪怕它含缺陷 Y)。一旦 category=物体(一物体多缺陷),该障眼法失效——物体的每张图都带该物体的某缺陷,故物体**没有任何真正的 good 图**。由于用途是零样本 AD,`train/good`/`test/good` 允许为空,此问题不致命。

## 目标

- 产出**物体为中心**的 MVTec AD 数据集:category=物体,物体内按缺陷分子文件夹。
- 人工只负责机器做不了的部分(把图指派给物体);脚本机械地完成其余。
- 可复现、可审计、能抓出人工分错的图。
- 不破坏现有 Option B 工具(保留为 legacy)。

## 非目标

- 不采集/合成干净图(零样本用途不需要)。
- 不做英文命名/翻译(服务器离线,物体文件夹直接用中文)。
- 不训练物体检测/分类器来自动判定物体(由人工分图解决)。

## 关键决策(已确认)

| 决策点 | 选择 |
|---|---|
| category 语义 | 物体(不是缺陷) |
| 物体身份来源 | 人工分图(半自动) |
| 交接方式 | 人建 `staging/<物体>/` 文件夹并放图;脚本按文件名回源查标注 |
| train/good | 留空目录(零样本用途) |
| 一图多缺陷 | 复制进每个缺陷子文件夹,mask 只留对应那类缺陷的多边形 |
| 物体文件夹命名 | 直接用中文(无 slug/映射表) |
| 物体清单 | 不需人工写;物体列表 = staging 下的文件夹名 |
| 可复现产物 | 脚本刷出 `object_manifest.csv` 作为审计/文档 |

## 架构:三段式流水线

### ① 探索(可选) — `convert_tools/seg_sample_browse.py`

目的:帮人肉眼归纳"有哪些物体"。产出**不是** MVTec,是给人看的中间物。

- 从源 seg 抽样 N 张(默认 500),连同每张的缺陷类别一起摊到一个浏览目录。
- 按缺陷分组;每张图配一个 sidecar(或汇总 CSV)列出其缺陷类别。
- 人据此在服务器上决定要建哪些物体文件夹。

此工具可选,不产出被后续步骤消费的东西——人看完直接进第②步。

### ② 人工分图(人做)

- 人建 `staging/<中文物体名>/`,把图片拖进去。
- 一张图只进一个物体文件夹(把多对多在此收敛成"每图一物体")。
- 人**只放图片**,不需要动标签、不需要写任何配置。

### ③ 生成 — `convert_tools/objectseg_to_mvtec.py`

单条命令,读 `staging/` + 源 seg,产出物体版 MVTec。步骤:

1. **建全局标签索引**:扫源 seg 的 `labels/{train,val,test}/*.txt`,建 `stem → 标签文件` 映射。**若出现重名 stem**(跨 split 或同 split),报错并列出冲突路径后中止(避免查错标签)。
2. **遍历每个物体文件夹**:对文件夹内每张图,用 stem 查索引拿到标签 → 解析出缺陷类别集合。
   - 图在源里查不到标签 → 记录并跳过,汇总报告。
   - 同一 stem 出现在两个物体文件夹 → 冲突,报告(人工分图出错)。
   - 标签为空(无多边形)→ 该图对此物体是 good,放入 `test/good/`(正常不会发生,但优雅处理)。
3. **发现缺陷子文件夹**:每个物体下有哪些缺陷,由该物体所有图的缺陷类别并集**自动决定**,不写死。
4. **写出 MVTec**(见下)。一图多缺陷 → 复制进每个缺陷子文件夹,mask 只保留该缺陷的多边形。
5. **刷出产物**:`object_manifest.csv`、每物体统计、报告(跳过/冲突/查不到)。
6. 从不修改源数据。

## 输出目录结构

```
<out>/<中文物体名>/
  train/good/                        # 空目录(零样本,保留以满足格式)
  test/good/                         # 空(无干净图;若偶有空标签图则落此)
  test/<中文缺陷名>/<stem>.png       # 该物体、该缺陷的图
  ground_truth/<中文缺陷名>/<stem>_mask.png   # 二值 {0,255} mask,仅该缺陷多边形=255,与图同尺寸
```

- mask 命名 `<stem>_mask.png`,二值 PNG,尺寸同原图(沿用现有 `make_mask` 逻辑)。
- 缺陷子文件夹名 = 源 `data.yaml`/`classes.txt` 里的类别名(中文)。

## object_manifest.csv 格式

审计与可复现产物,由脚本生成(非人工填写):

| 列 | 含义 |
|---|---|
| `stem` | 图片文件名(无扩展名) |
| `object` | 所属物体(= staging 文件夹名) |
| `orig_split` | 在源数据里的原始 split(train/val/test) |
| `defects` | 该图的缺陷类别(分号分隔) |
| `src_label` | 源标签文件相对路径 |

## 边界情况与处理

| 情况 | 处理 |
|---|---|
| staging 图在源里查不到标签 | 跳过 + 汇总报告 |
| 重名 stem(源索引冲突) | 报错列出冲突路径,中止 |
| 同一 stem 分到两个物体 | 报告冲突(人工分图错误) |
| 空标签图 | 落 `test/good/`(优雅处理,正常不发生) |
| 图片扩展名不一 | 索引/查图支持 `.jpg/.jpeg/.png/.bmp` |
| 输出已存在 | `--clean` 才清空,否则拒绝覆盖 |

## 与现有代码的集成

- 新增文件放 `convert_tools/`:`objectseg_to_mvtec.py`(必需)、`seg_sample_browse.py`(可选探索)。
- 复用 `yoloseg_to_mvtec.py` 里已验证的 `load_names` / `parse_label` / `make_mask`。
- 在 `convert.py` 的 `COMMANDS` 加新阶段 **"转 MVTec AD(物体版)"**,注册新工具。
- 旧的 `yoloseg_to_mvtec.py` / `seg2mvtec_interactive.py`(缺陷版 Option B)**保留为 legacy**,菜单里注明两者区别(缺陷版 vs 物体版)。
- 遵循仓库既有约定:单行 tqdm 进度条、缺依赖时的中文提示、`--src/--out/--clean` 风格。

## 已知局限(交付时需向多模态团队说明)

- `test/good/` 为空 → 无法计算图像级 AUROC(没有正常测试样本)。零样本团队通常只看像素级定位 + 文本,应可接受,但需在交付说明中写明。
