# 数据集质检抽样方案 v2（每类抽样 + 重复/冲突/错漏标 → 导出可在 X-AnyLabeling 复核的子集）

> v2 是联网调研后对 v1 的修订版。改动见末节「与 v1 的差异」。核心定调：**保持简单**，
> 产出 = 可直接在 **X-AnyLabeling** 打开复核的图片+标注子集，不引 FiftyOne/Cleanlab 重依赖。

## Context（背景与目标）

- 数据：约 **7.8 万张、约 299 类**，YOLO 格式（`images/labels/*.txt` + `data.yaml`），多人标注、规范性差。
- 已知四类问题：①重复标注 ②一物多签/层级冲突 ③错标 ④漏标。
- 目标：**每类至少抽 3 张样例（软下限，非硬指标）+ 充分暴露问题**，不做全量清洗。类别多的可适当多抽。
- 运行环境：服务器有 torch / lightly-train / dinov3，可传脚本与模型；**复核用已有的 X-AnyLabeling**。
- 约束：**实现别太复杂**。最终交付 = 导出图片 + 所需数据集子集。

---

## 一、为什么不能「每类独立抽 3 张」

数据是**多标签**（一图含多类）。独立抽会：图数爆炸+重复、稀有类凑不齐、抽到的是随机样例而非
「能暴露问题的样例」。正确做法 = **带配额的最大覆盖（贪心 set-cover，ln n 近似、O(nm)，7.8w 规模够用）**
+ **问题定向标记**。coreset 研究证实覆盖式选择优于随机；但其复杂版是为「挑训练子集提 AP」服务，
对纯质检看样例属过度设计，故 v2 只用**简单贪心覆盖**。

## 三、四步流水线（尽量简单）

### Step 0 — 体检（纯 CPU，一次扫描）
- 扫 `data.yaml` + 全部 `labels/*.txt`：每图 → {含类集合, 每框(类,cx,cy,w,h), 源子目录前缀, 图尺寸}。
- 一致性校验：`names` 长度==`nc`；**标签 id 越界**（≥nc，说明有人用了别的类表）；**零实例类**（names 有但全量 0 框，凑不齐 k=3）；图↔txt 缺配。
- 每类图数/框数/尺寸分布统计。

### Step 1 — 每类抽样（软下限 ≥3 + 问题优先 + 数据多的类上浮）
- **软下限**：每类配额 `quota = clamp(3, 3 + round(α·log10(类图数)), cap)`（默认 α≈3、cap≈10）——
  下限 3，类图数越多上浮越多但封顶，避免常见类（人员/车辆）刷屏。`quota`/`cap`/`α` 均可调，非硬指标。
- **问题优先**：先把 Step 2/3 命中 flag（dup/conflict/bad_box/missing/swapped…）的图纳入该类配额，
  优先用「能暴露问题的图」占满名额；不足再用贪心覆盖补普通样例。
- **贪心覆盖补齐**：维护每类剩余配额，反复挑「覆盖最多『仍欠配额』类」的图；并列时偏好共现类组合更新、
  框尺寸桶更全、源子目录更分散、位置哈希打散（避免连续帧近重复）。
- **稀有类**(图数 < 3)：有几张拿几张，报告标「样本不足」。
- 注：因为是软下限，最终每类实际张数会写进 `qc_report`，方便你看哪些类样例偏少需补看。

### Step 2 — 几何 + 层级查问题（纯 CPU，给每框/每图打 flag）
- **重复框**：同图两框 **IoU≥0.9 且中心/尺寸近乎一致** →`dup`。（阈值取严：拥挤场景里两人前后站位天然高 IoU，但不是重复——这是 NMS 的已知坑，不能用 0.85 一刀切。）
- **冲突标签**：两框 IoU 高且类别同属一组——`sibling`→`conflict`（如 suv vs 轿车）；`parent_child`→**合法不报**（车辆+suv）；`part_of`→**不报**（机翼+飞机）。
- **异常框**：极小(<4px)/整图(>95%画幅，常见灾害类误标)/越界/wh≈0 →`bad_box`。
- **超密集图**：单图框数 Top-N →`dense`（重复/漏标高发）。

### Step 3 —（可选 `--with-model`）错标/漏标，用你服务器的模型自实现 ObjectLab 逻辑
- 跑你的检测器（lightly-train 导出模型 / YOLO 预训练）得每图预测框。比对 GT：
  - 预测高置信但与所有 GT IoU 低 →`missing`（疑似漏标）；
  - GT 与某预测 IoU 高但类别不一致 →`swapped`（疑似错标）；
  - GT 与预测 IoU 偏低但有对应 →`loc`（框画得差）。
- dinov3 取每类 bbox 裁剪嵌入、算类内质心，离群 Top-N →`outlier`（错标交叉验证）。
- 仅排序+打 flag，**不自动改标**；不引 cleanlab。

### Step 4 — 导出可在 X-AnyLabeling 复核的子集（核心产出）
对 Step 1 选中 + Step 2/3 命中的图，非破坏性导出 `review_subset/`：
- **图片 + 同名 LabelMe JSON**（X-AnyLabeling 原生格式，打开文件夹即显示框+类名，无需导入步骤）：
  每个 shape：`label`=类名、`shape_type`=rectangle、`points`=两角点；**可疑框**把 flag 写进 shape 的
  `description`（如 `"DUP"`/`"CONFLICT:suv|轿车"`/`"MISSING?"`），**图级 flag** 写进 JSON 顶层 `flags`，
  复核时一眼定位问题框。
- 同时保留 `labels/*.txt`(YOLO 原样) + `classes.txt`：可走 X-AnyLabeling 的 Import，也可回灌训练，双向通吃。
- `qc_report.md` + `qc_report.csv`：覆盖表、零实例/配额不足类、各 flag 命中数与图名清单、id/一致性告警。
- `class_groups.yaml`：易混层级表（同时是给标注团队的清单）。
- contact sheet：**可选**（`--contact-sheet`），既然逐图在 X-AnyLabeling 看，默认不生成。

## 五、边界情况（已纳入）

- 多标签 → 必须覆盖式抽样+去重，否则图数爆炸。
- 零实例 / 配额不足类：单列报告，不静默。
- **id↔name 不对齐**：多人标注高发，先校验越界再抽。
- **重复 vs 合法多标签**：父子同框/部件-整体只标不判错，交人工在 X-AnyLabeling 裁决。
- **高 IoU≠重复**：拥挤同类目标阈值取严（≥0.9 + 中心尺寸近似）。
- 灾害/场景类整图框：单列，不误判为错标。
- 可复现：固定种子。非破坏：只读原数据，硬链接优先跨盘回退复制。
- 性能：Step 0–2 纯 CPU 一次扫描 + 图尺寸落盘缓存；Step 3 模型层分批、可跳过。
- k 可调（默认 3），稀有类向下取实际。

## 七、实现蓝图（保持简单）

- 一个可独立运行的脚本 `dataset_review_export.py`（放服务器跑，输入 `--data path/to/data.yaml`、
  `--k 3`、`--with-model <weights>`、`--contact-sheet`）；核心逻辑可放 `tool_lib/det_review_sample.py`
  便于复用现有 `common`/`det_shared`，但对外是一个简单 CLI，不进交互菜单也行。
- Step 0–2 不依赖 torch，可在任意机器先跑出覆盖子集+几何/层级 flag；Step 3 才需模型。
- 按 `tool_lib/tests/` 风格加少量单测：覆盖抽样达标、IoU 去重命中、层级冲突分类正确、零实例类报告、
  LabelMe JSON 能被 X-AnyLabeling 打开（结构校验）。

## 八、验证方式

- 小 det 数据集（如 `datasets/military_dataset/dataset_det` 或 coco 子集）跑 Step 0–2，人工核对：
  每类覆盖≥k、零实例类正确列出、人造重复/冲突框被命中且 flag 分类正确。
- 把 `review_subset/` 拷进 X-AnyLabeling 打开，确认框+类名+可疑 flag 正常显示、可编辑保存。
- `pytest`（WSL `lightlytrain` conda 环境）跑单测。
- Step 3 开 `--with-model` 在小集抽查 Top-N 错漏标是否指向真实问题。

## 九、与 v1 的差异（调研后修正）

1. **砍掉 FiftyOne**：你已有 X-AnyLabeling 做复核 UI，FiftyOne 重复且增复杂度。
2. **砍掉 Cleanlab 依赖**：ObjectLab 错漏标逻辑用你服务器现成检测器自实现，几十行，更轻。
3. **Step 1 简化**：不再搬训练向 `select_balanced_train_candidates`，改简单贪心覆盖（coreset 复杂版是为训练子集，不适配纯质检）。
4. **Step 2 阈值取严 + 层级感知**：IoU 0.85→0.9 且中心/尺寸近似；父子/部件同框判**合法不报**（Open Images 层级方案结论），只报兄弟冲突与真重复，避免误报刷屏。
5. **产出对齐 X-AnyLabeling**：主格式改 LabelMe JSON（打开即看、可疑框带 flag），并保留 YOLO 双向通吃；contact sheet 降为可选。

## 附录：方法与参考（联网调研 2026-06）

- 贪心 set-cover ln(n)/O(nm)：[CMSC451](https://www.cs.umd.edu/class/spring2025/cmsc451-0101/Lects/lect07-set-cover.pdf)
- coreset 优于随机、覆盖中心化：[CVPR2024 Coreset for OD](https://arxiv.org/pdf/2404.09161)、[Coverage-centric](https://arxiv.org/pdf/2210.15809)
- 层级标签/标注不全/不均衡 + Hierarchical NMS、父子同框合法：[Open Images 方案](https://arxiv.org/pdf/1810.06208)、[Imbalanced Multi-Labels](https://arxiv.org/pdf/2005.08455)
- 高 IoU≠重复（NMS 拥挤目标坑）：[Ultralytics NMS](https://www.ultralytics.com/glossary/non-maximum-suppression-nms)
- 错漏标 ObjectLab 三分数（参考自实现）：[Cleanlab OD](https://docs.cleanlab.ai/v2.6.6/tutorials/object_detection.html)、[论文](https://arxiv.org/pdf/2211.13993)
- X-AnyLabeling 导入 YOLO/原生 LabelMe JSON：[user_guide](https://github.com/CVHub520/X-AnyLabeling/blob/main/docs/en/user_guide.md)、[导入 YOLO issue#846](https://github.com/CVHub520/X-AnyLabeling/issues/846)
